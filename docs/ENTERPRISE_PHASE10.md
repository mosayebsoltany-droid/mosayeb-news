# فاز ۱۰ — آمار مدیریتی، کنترل نرخ و استعلام ساختگی هویت

نسخهٔ ۰٫۷٫۰ همچنان شبیه‌سازی است؛ اتصال به ثبت احوال، کاداستر یا بانک واقعی وجود ندارد. نقش admin تنها از CLI دارای دسترسی سرور ساخته می‌شود. حساب مدیر پیش‌فرض و ثبت‌نام عمومی برای ارتقای نقش ایجاد نشده است.

## دسترسی مدیر و آمار

```bash
# SQLite فعلی
# رمز به‌صورت تعاملی دریافت می‌شود؛ داخل دستور یا Git ننویسید.
docker compose exec broker python -m app.create_user review_admin --role admin
# یا در ترکیب مستقل PostgreSQL:
docker compose -f compose.postgres.yaml exec broker python -m app.create_user review_admin --role admin
```

این دستور یک حساب جدید می‌سازد و نقش حساب موجود را تغییر نمی‌دهد. ورود در `POST /auth/token` و سپس Swagger Authorize انجام می‌شود. `GET /analytics/dashboard` بدون توکن ۴۰۱، برای broker برابر ۴۰۳ و فقط برای مدیر فعال ۲۰۰ می‌دهد. هر درخواست، وضعیت فعال بودن و نقش فعلی حساب را از دیتابیس می‌خواند.

خروجی شامل تعداد کل، موفق، ناموفق، pending و نام فعال‌ترین broker است. به‌صورت پیش‌فرض ۳۰ روز تقویمی اخیر با تاریخ UTC (امروز و ۲۹ روز قبل) گزارش می‌شود. فیلترهای `start_date=YYYY-MM-DD` و `end_date=YYYY-MM-DD` شامل هر دو تاریخ‌اند؛ حداکثر اختلاف مجاز ۳۶۶ روز است. آمار از DocumentRequest، شامل ادعا و نقشه، می‌آید؛ دموی عمومی جداست. رد هویت پیش از ایجاد پرونده فقط در AuditLog می‌آید و جزو پرونده‌های failed نیست.

بهترین broker با بیشترین پروندهٔ موفق در همان بازه تعیین می‌شود؛ در تساوی، نام کاربری به‌ترتیب الفبا و سپس شناسه ملاک است. موفقیت‌های admin در رتبه‌بندی broker حساب نمی‌شوند. بدون نتیجه، `top_broker` برابر «نامشخص» است. شمارنده‌ها با یک aggregate query محاسبه می‌شوند. رتبه‌بندی query جدا دارد و زیر بار همزمان، snapshot تراکنشی یکپارچهٔ گزارش تضمین نشده است.

## کنترل نرخ

- `POST /services/claims`: پنج تلاش پذیرفته‌شده از نظر قالب و احراز هویت، در دقیقه برای هر شناسهٔ حساب. رد هویت و شکست سامانه نیز سهمیه مصرف می‌کنند.
- `POST /auth/token`: ده تلاش در دقیقه برای peer IP اتصال؛ حتی رمز نادرست سهمیه مصرف می‌کند.
- عبور از سهمیه: HTTP 429 با پیام عمومی و `Retry-After` (مدت کامل پنجره، به‌عنوان کران بالای امن).
- خرابی backend کنترل نرخ: HTTP 503؛ به حالت بدون محدودیت سقوط نمی‌کند.

کاربر نمی‌تواند با عوض کردن X-Forwarded-For در کد کنترل نرخ هویت حساب را تغییر دهد. IP ورود از `request.client` می‌آید؛ اعتماد Uvicorn/پراکسی به هدرها باید در استقرار فقط برای پراکسی‌های مورد اعتماد تنظیم شود. در NAT یا پراکسی مشترک ممکن است IP مشترک محدود شود. این قابلیت، دفاع کامل در برابر DDoS حجمی یا جایگزین WAF و کنترل لبهٔ شبکه نیست.

`BROKER_RATE_LIMIT_STORAGE_URI=memory://` پیش‌فرض تک‌پردازشی است؛ شمارنده با restart پاک می‌شود. برای چند پردازش از Redis اختصاصی مشترک استفاده کنید:

```bash
BROKER_RATE_LIMIT_STORAGE_URI=redis://redis:6379/0 docker compose -f compose.postgres.yaml --profile cache up --build --detach --wait
```

Redis این profile پورت عمومی ندارد. در این حالت شمارنده‌های کنترل نرخ در Redis هستند؛ نشست‌ها، کش تجاری و Circuit Breaker به Redis منتقل نشده‌اند. profile فعلی Redis ماندگار نیست، پس restart آن سهمیه‌ها را پاک می‌کند. برای شبکهٔ غیرمحلی، ACL/TLS و secret management مستقل لازم است. URI را در log/config منتشر نکنید. با تغییر URI، سرویس را recreate کنید. `/ready` علاوه بر دیتابیس، backend کنترل نرخ را هم بررسی می‌کند؛ قطعی آن ۵۰۳ و `/live` همچنان ۲۰۰ است.

## استعلام هویت آزمایشی

`GET /mock-registry/identity-check/{national_id}` شناسهٔ دقیقاً ۱۰ رقم ASCII می‌پذیرد؛ سایر قالب‌ها ۴۰۰ می‌گیرند. خروجی `simulation: true` دارد. فقط برای ساخت سناریوی تست، پیشوند ۹، `is_alive: false` می‌دهد؛ بقیهٔ پیشوندها true می‌دهند. این قاعده هیچ رابطه‌ای با حیات/وفات واقعی افراد یا اعتبار واقعی کد ملی ندارد.

ادعای احرازشده پیش از تماس ثبت، همین Mock داخل فرایند را با HTTPX/ASGI فراخوانی می‌کند. خروجی باید bool واقعی، شناسهٔ منطبق و نشانهٔ شبیه‌سازی داشته باشد. false باعث ۴۰۰ و رویداد `IDENTITY_REJECTED` می‌شود. timeout، 5xx، JSON خراب، فیلد ناقص، bool نادرست یا شناسهٔ نامنطبق باعث ۵۰۳ و `IDENTITY_UNAVAILABLE` می‌شود. در هر دو حالت تماس ثبت و ایجاد DocumentRequest انجام نمی‌شود؛ شناسهٔ ملی در متن audit ذخیره نمی‌شود. Retry و Circuit Breaker قبلی برای ارسال ثبت باقی‌اند. Mock هویت نام/نام خانوادگی ساختگی به اشخاص نسبت نمی‌دهد.

دموی بدون ورود `/api/demo/requests` گردش مستقل با مرجع DEMO دارد؛ هیچ استعلام هویتی دربارهٔ فرد انجام نمی‌دهد. URL شبیه‌ساز ثبت قابل تنظیم است، اما استعلام هویت این فاز عمداً فقط Mock داخل فرایند است و آداپتور بیرونی ندارد. اطلاعات واقعی اشخاص را در دمو وارد نکنید.

## معیارهای آزمون

- آمار دقیق بازه، گزارش خالی، تاریخ نامعتبر، تساوی رتبه، نقش broker/مدیر غیرفعال.
- پنج درخواست موفق، ششم ۴۲۹، سهمیهٔ مستقل کاربر دوم، عدم دور زدن با هدر جعلی.
- محدودیت ورود و خطای امن ۵۰۳ برای خرابی storage.
- شناسهٔ ۰۰۱۲۳۴۵۶۷۸ موفق در Mock، پیشوند ۹ رد و عدم تماس ثبت.
- خطا/ناسازگاری پاسخ هویت: رد بسته و audit، بدون ثبت پرونده.
- در CI: PostgreSQL واقعی، آمار admin، محدودیت مشترک با Redis، قطعی Redis و بازیابی readiness، همراه تست‌های قبلی.
