# معیارهای پذیرش سامانهٔ کارگزاری ثبت

این فهرست از برگهٔ ارزیابی ارسالی تهیه شده است. معیارها برای برنامه‌ریزی و آزمون‌اند و تأیید انطباق با سند تفصیلی محسوب نمی‌شوند.

| ردیف | موضوع | معیار پذیرش |
| --- | --- | --- |
| ۱ | راه‌اندازی سامانه | سامانه در محیط ارزیابی در دسترس و عملیاتی باشد. |
| ۲ | حداقل سه خدمت | هر سه خدمت از ابتدا تا انتها قابل اجرا باشند. |
| ۳ | ثبت ادعا | ثبت، ارسال، دریافت پاسخ و ثبت نتیجه با موفقیت انجام شود. |
| ۴ | درخواست تهیهٔ نقشه | فرایند کامل اجرا و پاسخ صحیح دریافت شود. |
| ۵ | درج گواهی اقدام ادعا | فرایند کامل اجرا و نتیجه ثبت شود. |
| ۶ | گردش کار | وضعیت‌ها، انتقال‌ها و پیش‌شرط‌ها مطابق فرایند مصوب باشند. |
| ۷ | API سازمان | تبادل برخط طبق رابط‌های اعلامی انجام شود و پاسخ و خطا درست مدیریت شوند. |
| ۸ | صحت و کامل بودن داده | نگاشت فیلدها و اعتبارسنجی مطابق ساختار مورد انتظار باشند. |
| ۹ | خطا و تراکنش ناقص | خطا ثبت شود و وضعیت ناسازگار ایجاد نشود. |
| ۱۰ | کنترل دسترسی | کاربر نتواند خارج از حدود نقش خود عملیات انجام دهد. |
| ۱۱ | ثبت رویدادها | اقدامات کلیدی از طریق Audit Trail قابل ردیابی باشند. |
| ۱۲ | مستندات | معماری، API و فرایندها با پیاده‌سازی منطبق و مستند باشند. |
| ۱۳ | محیط و سناریوی آزمون | سناریوهای پذیرش قابل اجرا و تکرار باشند. |
| ۱۴ | پایداری | سناریوها در اجرای تکراری بدون خطای بحرانی اجرا شوند. |

## وضعیت نسخهٔ ۰٫۱٫۲

رابط آزمایشی در مسیر `/portal` بالا آمده و بررسی سلامت پایگاه داده از رابط انجام می‌شود. این صرفاً بخشی از ردیف ۱ است. سه خدمت و الزامات ارزیابی هنوز تکمیل نشده‌اند.

برای اتصال واقعی و آزمون انطباق باید سند تفصیلی الزامات، فرایندهای مصوب، مشخصات رابط‌های سازمان و دسترسی مجاز به محیط آزمون دریافت شود. شبیه‌سازی با دادهٔ آزمایشی می‌تواند پیش از دریافت این موارد توسعه یابد.
